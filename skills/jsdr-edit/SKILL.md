# jsdr-edit: 인터뷰 편집 (가로 롱폼)

저장소는 `~/Projects/jsdr-studio` 에 받아 둔다. 모든 명령은 그 폴더에서 돌린다. 시작 전에 `RULES.md` 를 읽는다.

- 도구 `tools/jsdr_edit.py` (맥 기본 파이썬 `/usr/bin/python3`): prep, check, listen, dips, build, sheet, shorts
- 값 `config/jsdr.json`, 브랜드별 색과 글자 `config/themes/` (계획의 `"theme"`: `jinps` 진성형외과와 솔직한의사생활, `juvgen` JSDR 과 JUVGEN), 이 컴퓨터만의 자리 `config/local.json`
- 편집 계획 `plans/<편>-edit.json`, 작업물 `work/<편>/`, 편집 키트 `kit/` (logo.png, intro.mp4, outro.mp4, 자료 그림)
- 기준 계획 `examples/juvgen-sites-edit.json`. 새 편을 짤 때 옆에 두고 본다

편 이름은 영문 소문자와 숫자, 하이픈 (예 `juvgen-sites`).

## 편집 문법 (기준 영상에서 잰 것)

| 항목 | 값 |
|---|---|
| 길이 | 원본의 40~50%. 기준 편은 442초 → 본편 184초 (42%), 범퍼 포함 3분 30초 |
| 순서 | 인트로 4초 → PD 도입(지난 영상, 댓글, 오늘 주제) → 부위별 질문과 답 → 마무리 질문 → 아웃트로 23초 |
| 확대 | 넓게 1.09 (화면 끝 잡동사니를 잘라낸 값), 중간 1.3, 가깝게 1.45. 컷마다 단계를 바꾼다. PD 질문은 넓게, 원장님 답은 중간과 가깝게 번갈아 |
| 자막 | 한 줄, 아래 가운데, 흰 글자에 남색 번짐. PD 질문의 핵심 낱말 파랑(hl), 원장님 결론 한 줄 노랑(em) |
| 챕터 | 왼쪽 위 "번호 + 부위 이름". 질문이 시작되는 줄에서 켜고 다음 챕터까지 유지 |
| 로고 | 오른쪽 위 채널 로고, 처음부터 끝까지 |
| 댓글 카드 | 질문의 근거가 된 실제 댓글. 이름은 가리고 글은 그대로 |
| 큰 제목 | 오늘 주제 한 줄을 화면 가운데 크게, 화면은 어둡게 (기준 편 "합니다 vs 안 합니다") |
| 자료 화면 | 부위를 말할 때 전체 화면 그림 + 오른쪽 아래 동그란 원장님 창, 필요하면 흰 점선 원으로 부위 표시 |
| 소리 | 배경음악 없음. 본편 -14 LUFS, 이음매 8ms 페이드 |
| 색 | 거의 그대로. 어두운 쪽만 살짝 누른다 |

## 순서

### 1. 준비

    /usr/bin/python3 tools/jsdr_edit.py prep "<원본.mp4>" <편>

소리 크기로 말 덩어리를 나누고 (시각이 정확하다), 덩어리마다 전사하고, 얼굴 자리를 재고, 계획 초안을 쓴다. 3분쯤.
`work/<편>/<편>-transcript.md` 를 읽는다. 위쪽 덩어리 목록은 시각이 정확하고 글이 틀릴 수 있다. 아래쪽 전체 전사는 글이 더 정확하고 시각이 1초쯤 틀리다. 둘을 같이 본다.
화자 추정(pd, dr)은 소리 크기로 한 어림이라 자주 틀린다. 글을 읽고 고친다.

### 2. 편집 계획 쓰기

초안의 lines 가 원본 전체다. 줄을 지우면 컷이고, 순서를 바꾸면 재배치다. 줄 하나가 원본 [a, b] 한 조각이자 자막 한 줄이다.

무엇을 덜어내나:
- 촬영 준비, 마이크 확인, "본론으로 들어가겠습니다" 앞, 끝 인사 뒤 전부
- 같은 질문을 다시 묻는 대목과 그 답 (기준 편은 "만족하신 환자분들은" 재질문 60초를 통째로 뺐다)
- 주제에서 벗어난 비유, 질문을 나무라는 대목, 한 번 더 하는 결론 (기준 편에서 빠진 것: 사랑과 결혼 비유, "질문에 의미가 없습니다", "마술을 하러 가셔야", 가장 자신 있는 시술 문답)
- 문장 머리의 군말 ("그거는 왜냐하면", "그 다음에 그거는", "원칙을, 근본을 해결")

무엇을 남기나:
- 부위마다 질문 한 줄과 "합니다 / 안 합니다" 답, 그리고 이유 한 대목
- 질문과 답은 같이 남기거나 같이 뺀다
- 짧은 추가 질문은 본 질문들 뒤로 모으고, 전체를 아우르는 말과 마무리 질문을 맨 뒤에 둔다 (기준 편은 눈꼬리, 여드름 흉터를 앞으로 당기고 "쥬브젠이라는 거는" 총평을 뒤로 보냈다)

줄에 붙이는 것:

| 키 | 뜻 |
|---|---|
| `who` | `pd` 또는 `dr`. PD 줄은 넓은 구도가 기본 |
| `text` | 자막. 말한 그대로 쓰되 군말만 덜고 잘못 들은 낱말을 고친다. 한 줄 22자 안 |
| `hl` | 파랑으로 칠할 낱말 목록 (PD 질문의 부위 이름, 핵심어) |
| `em` | true 면 줄 전체 노랑 (원장님 결론: "그건 저는 안 합니다", "틀림없이 좋아져요") |
| `shot` | `wide`, `mid`, `tight`. 안 적으면 컷마다 알아서 바꾼다 |
| `chapter` | `{"n": 1, "title": "인디언주름"}`. 다음 챕터까지 유지, `false` 면 끈다 |
| `broll` | 자료 id. 계획 맨 위 `broll` 에 `{"img": "파일", "dots": [[cx, cy, rx, ry]], "pip": "br", "case": true}` |
| `card` | 댓글 id 또는 목록. 계획 맨 위 `cards` 에 `{"ago": "5개월 전", "text": "...", "pos": [x, y]}` |
| `title` | 큰 제목 한 줄 |
| `nocap` | 자막 없이 |

문장 안에서 자를 때는 덩어리 안쪽 시각이 어림값이다. 틈을 찾고 들어서 확인한다.

    /usr/bin/python3 tools/jsdr_edit.py dips <편> 98.3 101.6        # 그 사이 소리가 꺼지는 자리
    /usr/bin/python3 tools/jsdr_edit.py listen <편> 98.05 99.30     # 그 구간이 실제로 무엇으로 들리나

질문 끝과 답 시작이 붙어 있는 곳이 가장 자주 틀린다 (기준 편: "하나요?" 와 "그거는 안 합니다" 경계).

### 3. 자료 그림과 댓글

- 개념 그림 (부위가 어디인지 보여 주는 얼굴 클로즈업, 해부 그림): 병원에 있는 것이 먼저. 없으면 부위 설명용 그림을 만들어 `kit/broll/` 에 둔다. AI 로 만든 그림은 부위 설명에만 쓰고, 시술 결과나 전후 비교로 보이게 쓰지 않는다.
- 환자 사례 사진: 병원이 준 실제 사진만. 줄에 `"case": true` 를 달아 "※실제 쥬브젠을 이용해 치료한 환자 케이스" 표기를 넣는다. 환자 얼굴 공개 동의는 병원 쪽 확인 사항이라 납품 보고에 적는다.
- 댓글 카드: 채널 영상에 실제로 달린 댓글 글만 쓴다. 지어내지 않는다. 이름은 도구가 가린다. 댓글을 못 받았으면 카드를 빼고 보고에 적는다.
- 자료가 없는 줄은 `broll` 을 빼면 원장님 화면으로 간다. 빈 자리를 임시 그림으로 채워 납품하지 않는다.
- 동그란 창이 있는 줄은 자막이 짧아야 한다 (화면 폭의 44%). 넘으면 check 가 막는다. 줄을 둘로 나눈다.

### 4. 검사, 시험판, 눈으로 보기

    /usr/bin/python3 tools/jsdr_edit.py check <편>
    /usr/bin/python3 tools/jsdr_edit.py listen <편>             # 모든 줄 다시 듣기, 자막과 다르게 들린 줄
    /usr/bin/python3 tools/jsdr_edit.py build <편> --draft      # 1080p, 3분쯤
    /usr/bin/python3 tools/jsdr_edit.py sheet <편> --draft      # 장면 모음 (한 칸 2초)

check 의 "준법 확인 낱말" 은 자막, 제목, 댓글에 금지 표현이 들어갔다는 뜻이다. 원장님이 실제로 한 말이면 자르거나 바꾸지 말고 담당자에게 그 줄을 보여 준다. 우리가 쓴 제목과 강조면 고친다.
장면 모음 `work/<편>/qa/sheet_*.jpg` 를 Read 로 전부 본다. 볼 것:
- 넓은 구도 가장자리에 모니터, 조명 같은 잡동사니가 보이나 (보이면 config shots.wide 를 올린다)
- 가까운 확대에서 머리 위가 잘리나
- 자막이 동그란 창, 댓글 카드와 겹치나
- 챕터 번호와 내용이 맞나, 마지막 총평 줄에서 챕터가 꺼졌나
- 점선 원이 말하는 부위 위에 있나 (그림마다 dots 를 다시 잡는다)

촬영 환경이 바뀌면 다시 잰다. 얼굴 자리는 prep 이 매번 재지만, 구도가 다른 촬영이면 확대 배율과 face_target 을 프레임으로 보고 고친다. 지난 편 값을 그대로 믿지 않는다.

### 5. 최종판

    /usr/bin/python3 tools/jsdr_edit.py build <편>              # 4K, 4분쯤. 300MB 를 넘지 않게 화질을 맞춘다
    /usr/bin/python3 tools/jsdr_edit.py sheet <편>

도구를 고치거나 계획 몇 줄만 바꿨을 때는 전체를 다시 굽지 않는다. `build <편> --draft --only 5:13` 처럼 바뀐 줄만 구워 본다.
끝나면 결과 파일 자리, 길이, 음량, 뺀 대목 목록, 자료와 댓글 출처, 준법 확인 줄, 확인 못 한 것을 담당자에게 알린다. 올리는 일은 사람이 한다.

## 아직 손이 가는 곳

- 편집 키트의 로고, 인트로, 아웃트로는 원본 파일을 `kit/` 에 넣어 쓴다.
- 챕터 제목 손글씨는 나눔손글씨 펜으로 흉내 낸 것이다. 채널이 쓰는 서체 이름을 받으면 config chapter.title_font 를 바꾼다.
- 전환 효과음은 도구가 만든 임시 소리다 (`kit/sfx/whoosh.wav`). 채널이 쓰는 효과음을 같은 이름으로 넣으면 그것을 쓴다. 끄려면 계획에 `"sfx": false`.
- 썸네일, 제목, 설명은 이 스킬 범위 밖이다.

## 피드백 받으면

그 편의 계획 파일을 고친다. 같은 종류 실수가 다음 편에도 날 일이면 이 문서의 문법 표나 덜어낼 것 목록, 또는 `config/jsdr.json` 값을 고쳐 저장소에 올린다.
